Installation

You can install this library from Quicklisp, but you want to receive updates quickly, then install it from Ultralisp.org:

(ql-dist:install-dist "http://dist.ultralisp.org/"
                      :prompt nil)
(ql:quickload :reblocks-ui2)

Usage

All widgets are theme-aware: a widget knows nothing about the markup and is rendered by the current theme via the reblocks-ui2/widget:render generic function which receives the widget and the theme. To style the widgets with Tailwind, load the reblocks-ui2-tailwind system and make the Tailwind theme current before starting the server:

(ql:quickload :reblocks-ui2-tailwind)
(setf (reblocks-ui2/themes/api:current-theme)
      (reblocks-ui2/themes/tailwind:make-tailwind-theme))

Particular widgets are described in the sections below — Date Input, Charts, Confirmation Form and CRUD Table — and the full API reference is in the API section.

Date Input

function
reblocks-ui2/inputs/date-input:date-input
&key (widget-class 'input-widget) name value (format :iso) (required t) placeholder (view :normal) (size :m) disabled error

Returns a native HTML date input.

This is a thin constructor over the usual text input with :TYPE "date" and a valid-date validator attached.

VALUE should be a "YYYY-MM-DD" string, because this is the format browsers use for inputs with type="date".

FORMAT is passed to valid-date and only controls how the submitted data is parsed on the server. By default, the date is required; pass :REQUIRED NIL to allow empty values, in which case the validator returns NIL.

function
reblocks-ui2/form/validators:valid-date
&key (format :iso) (required t)

Returns a validator converting a date string into a local-time timestamp.

Two formats are supported:

  • :ISO (default) expects "YYYY-MM-DD" strings. This is a native format of the HTML inputs with type="date".

  • :DDMMYYYY expects "DD.MM.YYYY" strings.

When VALUE is empty and REQUIRED is NIL, the resulting validator returns NIL. An empty VALUE with the default REQUIRED = T signals a validation-error (1 2), as well as a VALUE which does not match the format or denotes a non-existent date like 2025-02-31.

function
reblocks-ui2/form/validators:format-date
timestamp &key (format :iso)

Formats TIMESTAMP as a date string.

Supported formats are the same as for valid-date:

  • :ISO (default) returns "YYYY-MM-DD" strings.

  • :DDMMYYYY returns "DD.MM.YYYY" strings.

A NIL TIMESTAMP is formatted as an empty string, so that the result can be used as an input widget's value.

Here is how a form with a native date input can be created:

(reblocks-ui2/form:form
 (reblocks-ui2/containers/column:column
  (reblocks-ui2/inputs/date-input:date-input
   :name "birthday"
   :value "2025-11-07"
   :required nil))
 :on-submit
 (lambda (form &key birthday)
   ;; BIRTHDAY is a local-time timestamp here, or NIL because
   ;; the date is optional in this example.
   (declare (ignore form birthday))))

The widget is a thin wrapper around a text input with type="date" and attaches a reblocks-ui2/form/validators:valid-date validator. The value is a "YYYY-MM-DD" string, native for the browser. Pass :format :ddmmyyyy to parse "DD.MM.YYYY" strings instead, and use reblocks-ui2/form/validators:format-date to convert a timestamp back into a string suitable for the widget's value.

Charts

function
reblocks-ui2/charts/pie-chart:pie-chart
data &rest restargs &key title column-names height background-color extra-options pie-hole is3d slice-colors (widget-class 'pie-chart)

Returns a pie chart widget rendered by Google Charts.

DATA is either a list of rows of the form (LABEL NUMBER-VALUE), or a function of zero arguments returning such a list. The function is called on each render to fetch fresh data.

PIE-HOLE is a number between 0 and 1, cut out from the center (0 for a usual pie chart, 0.4 for a donut).

IS3D turns on the pseudo-3D effect.

SLICE-COLORS is a list of CSS colors applied to the slices in order.

EXTRA-OPTIONS is a raw JavaScript string, inserted into the Google Charts options object before the closing bracket.

WIDGET-CLASS may be a subclass of pie-chart (1 2) to instantiate instead.

reblocks-ui2/charts/chart:chart-widget

Base class for chart widgets rendered by Google Charts.

Subclasses such as reblocks-ui2/charts/pie-chart:pie-chart (1 2) and reblocks-ui2/charts/column-chart:column-chart (1 2) define chart type specific options, theming methods do the rendering.

Charts are rendered by Google Charts:

(reblocks-ui2/charts/pie-chart:pie-chart
 '(("Alpha" 10)
   ("Beta" 25))
 :title "Tasks by mission"
 :column-names '("Mission" "Tasks"))

(reblocks-ui2/charts/column-chart:column-chart
 '(("2026-W1" 3)
   ("2026-W2" 7))
 :title "Users by week"
 :column-names '("Week" "Users")
 :x-title "Week"
 :y-title "Users")

DATA is either a list of (LABEL NUMBER) rows, or a function of zero arguments returning such a list. The function is called on each render, so charts always show fresh data. The Google Charts loader script is added as a widget dependency and requires no manual wiring.

Confirmation Form

function
reblocks-ui2/form/confirm:confirm
CONTENT &KEY (CONFIRM-BUTTON-TITLE "Confirm") (CANCEL-BUTTON-TITLE "Cancel") (CONFIRM-VALUE "submit") (CANCEL-VALUE "cancel") ON-CONFIRM WIDGET-CLASS

Returns a form widget asking the user to confirm an action.

CONTENT is a question to show to the user. It might be a string or any other widget and is processed by reblocks/widget:create-widget-from, like the content of the usual form.

The form contains two submit buttons sharing the name "button". The Confirm button submits CONFIRM-VALUE and the Cancel button submits CANCEL-VALUE. Both titles and values are customizable.

The Confirm button is the first submit button in the HTML. This way pressing Enter in the form submits it as if the Confirm button was pressed, because browsers use the first submit button for the implicit submission.

ON-CONFIRM, if given, is called with the form widget as the only argument, but only when the form was submitted with the button whose value is string-equal to CONFIRM-VALUE. Submission of the Cancel button does nothing. No persistence happens inside the widget, and no modal windows are hidden: to close a modal showing this form, call reblocks-ui2/modal:modal-hide from the ON-CONFIRM callback.

Use reblocks-ui2/form/confirm:confirm when an action has to be confirmed by the user. It returns a usual form with two submit buttons: Confirm and Cancel. The on-confirm callback is called with the form widget and only when the Confirm button (or Enter, because the Confirm button is the first submit button in the HTML) was used:

(reblocks-ui2/form/confirm:confirm
 "Delete this mission?"
 :confirm-button-title "Yes, delete"
 :on-confirm
 (lambda (form)
   (declare (ignore form))
   ;; Perform the action here.
   ))

The widget does not close modal windows by itself. When the form is shown inside a reblocks-ui2/modal:modal, hide the modal from the callback:

(let ((modal (reblocks-ui2/modal:modal
              (reblocks-ui2/form/confirm:confirm
               "Delete this mission?"
               :on-confirm
               (lambda (form)
                 (declare (ignore form))
                 (reblocks-ui2/modal:modal-hide modal))))))
  ;; Show the modal from some button's ON-CLICK callback:
  (reblocks-ui2/buttons/button:button
   "Delete mission"
   :on-click (lambda (button)
               (declare (ignore button))
               (reblocks-ui2/modal:modal-show modal))))

CRUD Table

function
reblocks-ui2/tables/crud:make-crud-table
columns data-getter &rest restargs &key add-form-maker edit-form-maker on-delete delete-question add-button-title edit-button-title delete-button-title edit-header delete-header add-header row-class widget-class

Returns a table widget with search and Add/Edit/Delete actions.

COLUMNS should not include an actions column: it is added automatically as the last column when at least one of ADD-FORM-MAKER, EDIT-FORM-MAKER or ON-DELETE is given.

DATA-GETTER is given as is to reblocks-ui2/tables/search:make-search-widget and should return a list of objects to show.

  • ADD-FORM-MAKER is called as (FUNCALL ADD-FORM-MAKER CRUD-WIDGET modal (1 2)) and should return a form widget.

  • EDIT-FORM-MAKER is called as (FUNCALL EDIT-FORM-MAKER modal (1 2) OBJECT) and should return a form widget.

  • ON-DELETE is called as (FUNCALL ON-DELETE OBJECT) after the user has confirmed the deletion.

When the library opens a form in the modal, it also subscribes to the form's :SUBMIT event, to update the table after a successful submission: the whole table is updated after the add form was submitted, and only the row's cells are recalculated after the edit form was submitted.

class
reblocks-ui2/tables/crud:crud-table

A search table with Add, Edit and Delete actions.

This widget knows nothing about the persistence: forms are created by ADD-FORM-MAKER and EDIT-FORM-MAKER callbacks, and the deletion is performed by the ON-DELETE callback. All of them are optional: only the corresponding buttons are rendered for the given callbacks.

A whole CRUD table can be created with a single reblocks-ui2/tables/crud:make-crud-table call. It renders a search table and adds an actions column with Edit and Delete buttons, plus an Add button above the table. Forms are created by the application and shown in a modal:

(reblocks-ui2/tables/crud:make-crud-table
 (list (reblocks-ui2/tables/table:column "Title"
                                         :getter #'task-title))
 ;; DATA-GETTER is given to the search widget and
 ;; returns the list of objects to show:
 (lambda (&rest args)
   (declare (ignore args))
   (copy-list *tasks*))
 :add-form-maker (lambda (crud-widget modal)
                   (reblocks-ui2/form:form
                    (reblocks-ui2/inputs/text-input:input
                     :name "title")
                    :on-submit (lambda (form &key button title)
                                 (declare (ignore form))
                                 (when (string-equal button "submit")
                                   (push (make-task title)
                                         *tasks*))
                                 (reblocks-ui2/modal:modal-hide modal))))
 :edit-form-maker (lambda (modal task)
                    ;; Should return a form editing the TASK.
                    ...)
 :on-delete (lambda (task)
              (setf *tasks*
                    (remove task *tasks*)))
 :delete-question (lambda (task)
                    (format nil "Delete this task: ~A?"
                            (task-title task))))

Each button is rendered only when the corresponding callback is given; without any callback the table has no actions column at all. The widget knows nothing about the persistence: saving objects inside the forms and deleting them in ON-DELETE is up to the application. After the add form is submitted, the whole table is updated; after the edit form is submitted, only the edited row's cells are recalculated. DELETE-QUESTION may also be a plain string.

REBLOCKS-UI2/FORM/CONFIRM

package
reblocks-ui2/form/confirm

Functions

function
reblocks-ui2/form/confirm:confirm
CONTENT &KEY (CONFIRM-BUTTON-TITLE "Confirm") (CANCEL-BUTTON-TITLE "Cancel") (CONFIRM-VALUE "submit") (CANCEL-VALUE "cancel") ON-CONFIRM WIDGET-CLASS

Returns a form widget asking the user to confirm an action.

CONTENT is a question to show to the user. It might be a string or any other widget and is processed by reblocks/widget:create-widget-from, like the content of the usual form.

The form contains two submit buttons sharing the name "button". The Confirm button submits CONFIRM-VALUE and the Cancel button submits CANCEL-VALUE. Both titles and values are customizable.

The Confirm button is the first submit button in the HTML. This way pressing Enter in the form submits it as if the Confirm button was pressed, because browsers use the first submit button for the implicit submission.

ON-CONFIRM, if given, is called with the form widget as the only argument, but only when the form was submitted with the button whose value is string-equal to CONFIRM-VALUE. Submission of the Cancel button does nothing. No persistence happens inside the widget, and no modal windows are hidden: to close a modal showing this form, call reblocks-ui2/modal:modal-hide from the ON-CONFIRM callback.

function
reblocks-ui2/form/validators:valid-date
&key (format :iso) (required t)

Returns a validator converting a date string into a local-time timestamp.

Two formats are supported:

  • :ISO (default) expects "YYYY-MM-DD" strings. This is a native format of the HTML inputs with type="date".

  • :DDMMYYYY expects "DD.MM.YYYY" strings.

When VALUE is empty and REQUIRED is NIL, the resulting validator returns NIL. An empty VALUE with the default REQUIRED = T signals a validation-error (1 2), as well as a VALUE which does not match the format or denotes a non-existent date like 2025-02-31.

With the default ALLOW-EMPTY = NIL an empty value signals a validation-error (1 2), like any other value which is not an integer.
